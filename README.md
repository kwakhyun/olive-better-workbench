# Better Workbench

OLIVE BETTER의 웰니스 MD가 `기획 요청 → 공개 트렌드 조사 → 신호 정제 → 상품 안전 검증 → AI-Driven UI 초안 → 검토·발행 → 고객 반응 재적용`을 한 흐름에서 수행하는 프론트엔드 중심 MVP입니다.

운영자 화면과 고객 화면은 분리되어 있습니다. 고객 화면에는 안전 검사를 통과해 발행된 JSON 화면 데이터만 표시됩니다.

## 실행

### 사전 조건

- Node.js `22.13.0` 이상
- npm
- 행사 가이드에서 제공하는 OpenAI 호환 LLM 연결 정보

```bash
cp .env.example .env.local
```

`.env.local`에 다음 값을 입력합니다.

```dotenv
LLM_API_URL=https://행사-연결-주소/v1/chat/completions
LLM_API_KEY=행사에서_제공한_인증값
LLM_MODEL=행사에서_제공한_모델명
```

최초 한 번 의존성을 설치합니다.

```bash
npm install
```

이후 아래 단일 명령으로 운영자 화면, 고객 화면, API 경계를 모두 실행합니다.

```bash
npm run dev
```

- 운영자 화면: `http://localhost:3000/`
- 고객 화면: `http://localhost:3000/shop`

### 기본 상태로 초기화

운영자 화면 왼쪽 아래의 **데모 초기화**를 누르면 아래 항목을 한 번에 지웁니다.

- 작성 중인 초안
- 고객에게 발행된 결과
- 클릭·좋아요·모의 구매 기록
- 공개 소스의 이전 성공 조사 캐시

## 확인하기 좋은 데모 순서

1. 운영자 화면에서 기본 요청으로 **트렌드 조사 & 초안 만들기**를 누릅니다.
2. 단계별 로딩 상태와 공개 소스의 출처·수집 시각·관련도를 확인합니다.
3. 오른쪽 **근거**, **제외·안전**, **화면 JSON** 탭을 확인합니다.
4. 대표 배너 제목을 `질 병-치료 100 % 효과`로 바꾸어 발행 버튼이 차단되는지 확인한 뒤 안전한 문구로 되돌립니다.
5. 상품 카드에서 **제외**를 눌러 미리보기와 JSON이 함께 바뀌는지 확인합니다.
6. **고객 화면에 발행**한 뒤 `/shop`에서 발행 결과를 확인합니다.
7. 고객 화면에서 같은 상품의 상세 보기, 좋아요, 구매를 차례로 누릅니다.
8. 운영자 화면으로 돌아와 같은 요청으로 다시 초안을 만듭니다.
9. 상품 수가 `10 → 14`로 늘고, 반응한 영역이 앞쪽으로 이동하며, 해당 상품에 `고객 반응 11점` 근거가 붙는지 확인합니다.
10. 공개 소스를 실패시키면 이전 성공 자료의 기준 시각과 전환 이유가 표시되는지 확인합니다.

반응 가중치는 클릭 `1`, 좋아요 `3`, 구매 `7`입니다.

## 구현 범위

### MUST

- **단일 실행 명령**: `npm run dev`
- **실제 공개 트렌드 연결**: Google News RSS, OpenAlex API를 서버 경계에서 병렬 조회
- **실제 LLM 연결**: OpenAI 호환 Chat Completions API로 대표 배너 문구 생성
- **정제 감사 로그**: 중복, 광고, 의약품·질병 질의, 오래된 자료, 낮은 관련성의 제외 사유 보관
- **상품 안전 검증**: 품절, 건강 기능 누락, Well-기능 불일치, 동일 상품 중복 제외
- **AI-Driven UI**: JSON의 영역 종류·순서·내용·표현 옵션으로 화면 조립
- **MD 검토**: 대표 문구 수정, 상품 제외, 미리보기, 근거·안전·JSON 확인
- **발행 통제**: 발행본만 고객 화면 노출, 실제 LLM 문구가 없거나 안전 검사 실패 시 차단
- **반응 재적용**: 현재 브라우저 세션의 클릭·좋아요·구매를 상품 점수·상품 수·영역 순서에 반영
- **문구 안전**: 공백·기호로 우회한 질병·과장·의약품 표현까지 정규화 후 재검사
- **복구 상태**: 조사/생성 로딩, 캐시 전환, 연결 실패, 자료 부족, 빈 발행 상태 구분
- **부분 오류 격리**: 모르는 화면 영역은 운영자에게 알리고 해당 영역만 건너뜀
- **네트워크 없는 자동화 테스트**: 핵심 위험 12개 테스트
- **실행 화면 증거**: `/screenshots`에 Playwright 기반 캡처 저장

### 구현한 SHOULD

- 생성 단계별 진행 상태
- 실패 시 이전 성공 조사 자료 복구
- 화면 영역 레지스트리 기반 확장
- 같은 실행에서 좋아요·구매 상태 및 반응 점수 공유
- 구매 신호 상품 우선 정렬과 추천 상품 수 확대

### 구현하지 않은 SHOULD

- A/B 테스트와 통계적 승자 판정
- 여러 고객군을 사용한 장기 개인화
- 실제 회원 인증과 결제
- 쿠폰 계산, 상품 옵션 선택의 전체 주문 상태
- 추가 이미지·검색 생성 모델 연결

## 데이터

과제 설명에 적힌 원본 `data/products.json`, `data/rules.json`은 전달된 첨부 폴더에 포함되어 있지 않았습니다. 실행 가능한 제출물을 위해 다음을 포함했습니다.

- `data/products.json`: 정확히 300개인 결정적 데모 카탈로그
- `data/rules.json`: 금지 문구와 6대 Well별 허용 기능 규칙
- `scripts/generate-demo-data.mjs`: 같은 300개 데이터를 다시 만드는 생성기

데모 카탈로그에는 품절, 기능 누락, Well-기능 불일치, 중복이 의도적으로 섞여 있습니다. 실제 제공 파일을 `data/products.json`, `data/rules.json`에 같은 필드 이름으로 교체하면 엔진은 그대로 사용합니다.

## 화면 구성 JSON

```json
{
  "schemaVersion": "1.0",
  "status": "draft",
  "well": "Fit Well",
  "theme": "습한 계절에도 흐트러지지 않는 루틴",
  "palette": {
    "accent": "#FF8D67",
    "soft": "#FFE5DD",
    "ink": "#172018",
    "canvas": "#FAFAF6"
  },
  "blocks": [
    {
      "id": "hero",
      "type": "hero",
      "variant": "editorial",
      "title": "비 오는 날에도, 내 리듬은 가볍게",
      "productIds": ["P0001", "P0002"]
    },
    {
      "id": "editors-pick",
      "type": "product_rail",
      "productIds": ["P0001", "P0002"],
      "presentation": {
        "density": "airy",
        "emphasis": "first"
      }
    }
  ]
}
```

주요 설계 이유:

- `blocks[]`의 순서가 고객 화면의 실제 순서입니다.
- `type`은 렌더러 레지스트리에서 영역 컴포넌트를 선택합니다.
- `presentation`은 같은 영역도 격자, 가로 넘김, 강조·색상 방식이 달라지게 합니다.
- 상품은 `products` 사전에 한 번만 보관하고 영역은 `productIds`로 참조합니다.
- `audit`에는 상품·신호 제외 사유, 문구 안전 결과, 반응 재적용 설명을 보관합니다.
- 지원하지 않는 `type`은 전체 화면을 깨뜨리지 않고 해당 영역만 격리합니다.

## 외부 연결과 mock 경계

### 실제 연결

- `app/api/research/route.ts`
  - Google News RSS
  - OpenAlex Works API
- `app/api/generate-banner/route.ts`
  - 행사 제공 OpenAI 호환 LLM

대표 배너 API는 브라우저에 비밀 키를 노출하지 않습니다. `LLM_API_URL`, `LLM_API_KEY`, `LLM_MODEL`을 서버 환경 변수로 읽습니다.

### mock

- 상품 이미지: CSS 기반 가상 패키지
- 회원: 브라우저 한 개를 한 고객 세션으로 취급
- 구매: 결제 없이 구매 이벤트만 기록
- 영속 저장: `localStorage`; 실제 서비스에서는 발행본·반응·조사 캐시를 DB/이벤트 스트림으로 교체
- `TEST_CONNECTORS=true`: 자동화와 스크린샷 전용 공개 소스·LLM mock. 기본 실행에서는 꺼져 있으며 실제 연결을 대체하지 않습니다.

실서비스 전환 지점:

- `localStorage` → 발행 DB, 행동 이벤트 스트림
- CSS 패키지 → 상품 CDN 이미지
- mock 사용자 → 회원/동의 기반 고객 식별자
- 모의 구매 → 주문 완료 이벤트

## 공개 소스 실패 전환

성공한 조사 응답은 가져온 시각과 출처를 포함해 브라우저에 저장합니다. 다음 조사에서 모든 공개 소스가 실패하면:

1. 이전 성공 자료가 있으면 `cached` 상태로 전환
2. 원래 자료의 기준 시각을 유지
3. 전환 이유를 운영자 화면에 표시
4. 캐시가 없으면 초안을 억지로 만들지 않고 재시도를 안내

LLM 실패 시에는 화면 검토용 기본 문구만 보여 주고, **실제 LLM 생성 문구가 아니므로 발행은 차단**합니다.

## 테스트

네트워크와 외부 키 없이 실행합니다.

```bash
npm test
```

프로덕션 빌드와 렌더링 테스트까지 한 번에 확인:

```bash

```

검사 범위:

- 서로 다른 입력에 따른 테마·상품·영역 차이
- 정상 신호 정제와 실패 캐시 전환
- 대표 배너 반영
- 품절·기능 누락·불일치·중복 제외
- 문구 우회 표현 안전 검사
- 초안 차단과 발행 조건
- 고객 반응 재적용

- 알 수 없는 화면 영역 격리

## 주요 한계

- 행사 LLM의 호출 스키마는 OpenAI Chat Completions 호환을 전제로 합니다.
- 공개 뉴스의 사용 가능 여부와 응답 속도는 원 소스 정책에 영향을 받습니다.
- 브라우저 저장소 기반 MVP이므로 여러 기기·사용자 간 발행 상태를 공유하지 않습니다.
- 웰니스 추천은 상품의 등록 기능 적합성을 검사하지만 의료 조언을 제공하지 않습니다.
